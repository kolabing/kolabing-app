`IF-37` · issue **#171** · PR **#172**

roughly **19,900 lines across 102 files** sat on `feat/multi-kolab-event-mvp`, cut from a `master`

### 1.2 Challenges and the People Layer — ✅ Merged
`IF-27` · `IF-30` · `IF-39` · issues **#140**, **#183**, **#188**

The challenge system was a receipt printer for two people already standing next to each other: no
reason to exist before the event, no memory after it, no awareness of the room. This release gives
it a camera, a ledger of people, and a way in for someone who does not have the app yet.

- Event-challenge QR loop end to end: check-in → peer scan → challenge → XP.
- A peer challenge **pays both sides from one scan** on a shared screen — three scans became one.
- Challenge library, challenge-first flow, and the full request lifecycle.
- **Camera challenges:** the camera holds the moment, the reveal ends on the person rather than the
  number, and XP is paid *before* the photo uploads, so venue wifi never costs anyone the moment.
- **Encounters** — the People Layer ledger — plus **ghost invites**: the person without the app can
  be invited, and the code reaches them.
- Authoring from the app: a leader sets whether a challenge opens the camera.
- `proof_type` is read from the field the backend actually sends.

## 2. The backlog is lying to you

**Four issues read as open work but shipped on `master` days ago.**

The cause is *not* the release branch — every one of these PRs merged into `master`, verified with
`git merge-base --is-ancestor`. The cause is the closing keyword in the PR body:

| Issue | Merged as | Base | Merged | Body says | Issue state |
|---|---|---|---|---|---|
| **#171** Multi-Kolab mobile revival | PR #172 | `master` | 26 Aug | `Refs #171` | 🔓 open |
| **#183** Camera challenges + People Layer | PR #184 | `master` | 27 Aug | *"The app half of #183"* | 🔓 open |
| **#188** Manage challenges from the app | PR #189 | `master` | 27 Aug | `Refs #188` | 🔓 open |
| **#176** Cover upload reports false success | PR #177 | `master` | 27 Aug | `Refs #176` | 🔓 open |
| **#174** One community page | PR #175 | `master` | 26 Aug | **`Closes #174`** | ✅ closed |

`Refs #n` is not one of GitHub's closing keywords. Only `close`/`closes`/`closed`,
`fix`/`fixes`/`fixed` and `resolve`/`resolves`/`resolved` auto-close. **#174 is the control case:**
the one PR that wrote `Closes` is the one whose issue closed by itself.

**Before closing, check each one — two are unambiguous, two are epics:**

- **#176** (PR #177) and **#188** (PR #189) map one-to-one onto their PR. Close them now.
- **#171** and **#183** are epics with a second half. PR #184 calls itself *"the app half of #183"*
  and names `kolabing-v2#216` as the backend half; PR #172 "revives" the Multi-Kolab MVP against a
  backend that shipped as `kolabing-v2#141`. Confirm the other half is done before closing, or
  convert them into tracking issues so the app work stops counting as outstanding.

**Fix for next time:** the PR template should require `Closes #n`, not `Refs #n`, whenever the PR
completes the issue.

## 2b. `master` and `release/1.6.0` have diverged

Worth knowing before the release merge. `origin/master` is **17 commits ahead** and
`origin/release/1.6.0` is **10 commits ahead** — but the *trees* differ in only 12 files, because
two things were merged into each branch separately rather than merged once and forwarded:

- **PR #192** (event reminders) has two merge commits: `0906e2d` on `master` (the real PR merge) and
  `3ed0549` on `release/1.6.0`.
- **The `Podfile.lock` / `app_links` fix** likewise: `ce6b19d` on `master` (PR #190) and `227b1c4`
  on `release/1.6.0`.

Content parity is otherwise intact — including `dc3159d` (*restore deleted prefs tests, stop the
events toggle snapping back*), which is present on both.

**Two commits exist only on `release/1.6.0` and have never reached `master`:**

| Commit | Work |
|---|---|
| `b667a76` | `feat(brand)`: the animated K replaces the wordmark and the cloud logos |
| `76ce624` | `fix(community)`: the points/tier band leaves a member's community page |

They are real code — 12 files including `kolabing_k_mark.dart`, `splash_screen.dart`,
`kolabing_app_bar.dart` and `community_detail_screen.dart`. They ship in 1.6.0, but if 1.6.0 is ever
abandoned rather than merged, they are lost. Merge the release branch back into `master` rather than
cherry-picking from it.
